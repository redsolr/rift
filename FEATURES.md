# Tactician — capability map

What the product does **today**. Update in the same commit as any feature-visible change. ✅ shipped · 🟡 partial · 🔲 planned (see `docs/concept.md`) · 🚫 deliberately not now.

## Engine (`src/sim`) — 2026-08-17

- ✅ Deterministic battle: `Battle(config, seed)`; mulberry32 RNG; identical logs for identical inputs (vitest-guarded).
- ✅ Grid: 16×12 default (river across the middle, three fords, forests on the flanks, hills, wall stubs); terrain = ground / forest (+2 def, cost 2) / hill (+1 def, cost 2) / water (impassable) / wall (impassable) / objective (+1 def). Dijkstra movement; enemies block, allies pass-through.
- ✅ Combat: `damage = max(1, atk + attack power − (def + terrain))`; healer heals `atk + power`; death; win when a side is wiped; draw at `maxTurns`.
- ✅ **Four attacks per unit (2026-08-18, `sim/attacks.ts`)** — Pokémon-style placeholder set per archetype (FE "combat arts" in spirit): each attack = flat **power** on atk, a **range** (or the weapon's own) and a **movement condition** — *stationary* (only without moving: Shield Bash / Cleave / Snipe / Blaze / Mend, +3) or *moved* (only after moving: Charge / Rush / Flare / Quick Heal, +1..+2) — plus a longer-reach lighter one (Long Thrust / Wide Swing / Quick Shot / Long Shot / Ember / Far Heal). Deterministic, no accuracy yet. `Action.attack` names the attack id (attacks AND heals); `attack`/`heal` events carry its name; `Forecast.attack` = the one forecast. Engine validates the whole action **before** moving (a rejected attack no longer leaves the unit displaced). Threat tiles / danger zone = union of all four ranges. AI picks the best usable attack per (tile, target) — candidate labels read `Snipe → Wren`, the Damage term names it. Each attack has a **kind** (attack / heal): the healer owns three heals + **Staff Bash** (−3, adjacent) — every unit has at least one damaging attack; heals target wounded allies, attacks target enemies; `act()` refuses a kind mismatch. Threat tiles / danger zone use damaging attacks only.
- ✅ Turns: `firstTeam` phase → other phase (default red; the default config sets blue = the player); speed order within a phase (ties by id).
- ✅ Five archetypes: Knight, Fighter, Archer (range 2–3), Mage (1–2), Healer (1–2), each with default stats + personality.
- ✅ Utility AI with named score terms per candidate (attack / heal / move / wait); `decision` events carry the top-6 candidates.
- ✅ Personality (aggression, courage, discipline, intelligence, loyalty): discipline = order adherence + whim jitter; intelligence gates exposure/counter-risk (≥35) and focus-fire/overkill (≥70); courage scales exposure fear.
- ✅ Orders per unit: stance (hold/advance/pursue), target preference (nearest/weakest/wounded/ranged/healers), protect <ally>, avoid armored, do-not-pursue, retreat-below-HP%.
- ✅ Doctrine per team: aggression (very defensive → all-out) + objective (hold/advance/capture/protect).
- ✅ Event log = the only renderer input: turn_start, decision, move(path), attack, heal, wait, death, end.
- ✅ `runMany(config, seeds)` batch stats: win rates, avg turns, deaths/survivals per unit. `npm run sim -- N`. ~3.5 ms/battle.
- ✅ Share codes: config ⇄ URL-safe base64 (`#c=…`).
- 🔲 Counterattacks, accuracy/crit, status effects, morale, command range, height, fog — only after the loop proves fun.

## Modes (`src/store`, `src/components`)

- ✅ **Manager**: set orders/doctrine → Start → command phase → Execute 1/3/5/all turns → watch → adjust → repeat. Both sides AI.
- ✅ **Manual — DEFAULT mode on load (2026-08-18) — FE command flow**: you control blue; click unit → blue reachable tiles → click tile → the card **previews on the new tile** and the in-board **command menu opens right away** (FE Three Hopes look: ink-smoke cloud — SVG turbulence-displaced blobs blurred so the edge FADES rather than blocks, half-transparent panel — hanging well to the RIGHT of the unit so it never covers the card, serif rows with ◆ bullets and hairlines, fixed columns, gold band + ➤ hand cursor on the hovered row): `Attack` · `Heal` (only for units that own heals) · `Wait` · `Cancel` (rows disabled with "—" when nothing is in reach). **Right-clicking one of your own units opens this menu at its current tile immediately** — no left-click first. Attack/Heal → the **attack picker** (that kind only): the unit's four attacks with power (+3 / −2 / ±0), range, and why a row is off ("must stand still" / "needs a move first" / "nothing in reach"); hovering a row previews its range on the board and its forecast in the battle bar. Pick one → **target step — the menu closes**; a single centred FE prompt (`▸ WIDE SWING · click a red target (n)` / `Right-click empty · back`) + red (or green for heals) target tiles + the battle-bar numbers carry it; click/right-click a target commits, right-click anywhere else backs out. `Back`/`Cancel`/**Esc** step back one page (target → picker → command → un-place). Fast paths stay: right-click an enemy (or click a red target from the command page) attacks with the **best usable attack** from that tile. **Right-click** = Civ-style one-click order: move to a reachable tile, or attack an enemy (from the current tile, or from a reachable tile in range); right-*drag* still pans (a drag never orders). **Esc** cancels the pending move / deselects. **Turn controls bottom-right of the board (2026-08-18)**, riding just above the battle bar (`--bb-h` published by the bar via ResizeObserver): **END TURN** = your remaining units act on their orders, then the enemy phase; **▶ AUTO** toggle = the AI plays *your* phases too (orders/doctrine) until you press ■ Auto again — switching it on during an idle phase of yours plays it out immediately. (Removed the duplicate End-turn button from the top HUD.) Walls are 0.6 tall to limit occlusion at the 45° angle.
- ✅ **Editor — map library (2026-08-18)**: a **Maps** section at the top lists every saved setup (terrain + units + doctrine + max turns) in **play order** (▲/▼ reorder, ✕ delete, rename inline, "+ Blank map", "+ Duplicate"); click a row to work on it; **every edit autosaves into the active map** (localStorage `tactician.maps`, hydrated on mount — SSR renders the default). Loading a share code / the default setup **detaches** ("Unsaved setup — save as map") so it never overwrites a map. Manual/Manager play whatever map is active. No campaign flow yet — the order is the plan for one.
- ✅ **Editor**: click-drag terrain painting, place/erase/move units for either team, edit stats/name/team/archetype, resize map, max turns, clear terrain; **Run once** (watch), **Run 10/100/1000/5000×** with win bar + deaths/survivals; live personality sliders + orders on any unit.
- ✅ Playback: play/pause/step, 0.5–4× speed, event cursor; Rematch = next seed; Reset = back to setup.
- ✅ "Why did it do that?" — selected unit's last decision: ranked candidates, expandable term breakdown (Explain panel).
- ✅ Share: copy link (`#c=code`), paste to load, load default setup.
- ✅ **FUT-style unit cards (2026-08-17)**: units are billboarded cards (procedural canvas texture in `components/cards.ts`, cached per team/archetype/name/stats): team-colored shield frame with gold trim, big overall rating (calibrated 84–92 across the five archetypes) + position code (KNT/FTR/ARC/MAG/HLR), archetype glyph "portrait" with glow, name band, six-stat row HP·ATK·DEF·SPD·MOV·RNG, team crest. Acted units dim; ground shadow blob; HP bar + name label float above. The same art appears as portraits in the combat forecast. No character artwork yet — the generator is the slot for it.
- 🟡 Presentation: Three.js board (r3f), HP bars, name labels, hop-on-attack, shake-on-hit, floating damage/heal numbers, tile highlights (reach / target / selected / hover / **attack-range diamond of the selected unit**). **Effects (2026-08-17)**: archer = arcing arrow projectile + impact flash; mage = cast glow → glowing bolt with trail + point light → vertical impact flash; melee = slash arc; heal = rising green ring at healer and target. Effects are spawned from events (never from engine state). No sprites yet.
- ✅ Battle log (panel section): human-readable turn-by-turn feed derived from the replayed events (moves, hits with damage/HP-left/KILLED, heals, waits, result); auto-scrolls; click a row to select that unit.
- ✅ **Mobile = LANDSCAPE (2026-08-17)**: coarse-pointer devices get a phone layout; portrait shows a "turn your phone sideways" gate. Landscape: single-row compact HUD (icon buttons, no speed select), the panel lives in a right-side **drawer** (34px rail → tap to open, ~320px), the board fills the rest, a contextual hint pill sits top-center ("Your move — tap a red unit", "Command phase — set orders, then Execute", result). One-finger pan, two-finger pinch/rotate; 40px touch targets; 16px inputs (no iOS zoom); safe-area insets; `apple-mobile-web-app-capable`. Solo forecast card hidden on phones (duel card only).
- ✅ **FE3H-style camera (2026-08-17)**: fixed viewing angle (default 45°, adjustable 30–70° in the camera widget, persisted), no orbit anywhere. **RTS edge-scroll**: mouse within 28px of the board edge pans that way (mouse only, cancels glides, clamped to the map; toggle in the widget). **Camera widget** bottom-right of the board: zoom +/−, ⤢ Overview, ◎ Follow, 🎥 settings (angle slider, edge-scroll, follow). Opens on the whole battlefield; during playback it **pans** (no zoom change — zoom stays where you set it) to whoever is acting (move end / attack midpoint / heal midpoint), does **not** move when you merely select a unit (2026-08-18 — only movement/actions pan), and stays put when a unit finishes or a phase ends (no snapping back to overview — only the end of the battle pulls back). Any user gesture cancels an in-flight glide. Desktop: wheel = zoom, right/middle-drag = pan, left = select only. Phone: one finger = tap, two fingers = pan + pinch-zoom. Overview / Follow live in the camera widget (Follow off = camera never moves by itself).
- ✅ **You are BLUE, on the near side (2026-08-17)**: default map 16 wide × 12 tall; blue (you) starts on the near bank (rows 10–11) and **moves first** (`BattleConfig.firstTeam`, carried in share codes), red (enemy) holds the far bank; the camera always sits behind you, FE-style.
- ✅ **Hover preview (2026-08-17)**: with a unit selected, hovering any reachable tile shows the yellow destination tile, the yellow movement path with an arrowhead, the red attack squares from *that* tile and the threat arcs — exactly the FE3H cursor read; clicking then commits/previews as before.
- ✅ **Phase banners**: PLAYER PHASE / ENEMY PHASE (blue / red rotating rune circle + star lattice + big text, ~1.25 s, scaled by playback speed) on every phase start; VICTORY / DEFEAT / DRAW at the end. `turn_start` playback hold is 1.3 s so the banner reads.
- ✅ **FE range paint (Three Hopes overlap)**: select a unit → movement field lights **blue with a light edge**; the ring it can attack into but not stand on lights **red**; the attack range from where it STANDS (or the hovered / pending tile) is laid over the blue as **pink with an orange edge**, so the overlap reads at a glance (green for healers). Enemy selection shows both in red. Danger zone (every tile the enemy can reach next activation) is a magenta wash, **off by default** — HUD ◆ toggle.
- ✅ **Character box** bottom-left (FE style): hovered unit else selected — name banner, overall, class, HP + bar, weapon + range, card portrait, and the terrain under it (or under the cursor) with its Def/cost.
- ✅ **FE Engage-style battle bar (2026-08-18)** — replaces the earlier top-left forecast card and the bottom-left character box. Spans the bottom of the board: **your unit bottom-left** (card portrait, name + overall, class, HP, weapon + range, terrain), **enemy bottom-right** mirrored, **middle = outcome**: `Crit · Hit · HP | HP · Hit · Crit` header, damage shown on the receiver's side (`-8` under the enemy, `-4` under you, red ✕ when it cannot hit back), predicted HP bars with striped "to lose" segment and the big predicted numbers (red when lethal), and a **RIGHT-CLICK ▸ ATTACK** prompt (the A-button; "TAP TARGET ▸ ATTACK" on phones; "Out of range from here"). The bar opens only for a **selected** unit (hover alone never opens it); the enemy side fills in when you hover an enemy while one is selected. Numbers from `Battle.forecast()` for the **chosen (or hovered) attack**, else the best usable one — the prompt reads `SNIPE · RIGHT-CLICK ▸ ATTACK`, the weapon line shows the attack name + its range; retaliation = the defender's best answering attack from where it stands. Hit 100 / Crit — until accuracy exists.
- 🚫 Turn-order strip — built then removed 2026-08-18: FE has no in-phase order, you move any unit freely; the strip suggested a sequence that does not exist.
- ✅ **Big RTS/FE-scale character panels** in the battle bar: 150px card portrait, 30px name, class + HP bar, weapon + range, ATK/DEF/SPD/MOV chips, terrain; container queries step it down when the board is narrow (< 1250px / < 900px) and on phones.
- ✅ **Target focus**: the enemy under the pointer gets a pulsing bracket frame on its tile (gold when it is a valid target from your pending tile, red otherwise).
- ✅ **Minimap** top-right: terrain + unit dots (blue you / red enemy / gold ring selected); click to look there. Camera widget sits under it.
- ✅ **Threat arcs + danger zone**: thin **glowing** red arcs (soft glow ribbon + flowing dashes + pulsing tip) from every enemy that could attack the selected unit where it stands, on the tile it is **hovering** (FE cursor preview — no confirm needed), or on the pending tile; hovering one of your units with nothing selected shows who threatens it; yellow arc to the target being considered; FE-style **danger zone** (every tile the enemy team can attack next activation, `Battle.threatZone`) as a red wash; selected unit's attack range as a strong orange diamond. HUD **◆ Danger** toggle (off by default).
- ✅ LAN testing: `npm run dev` binds `0.0.0.0:3030` — open `http://<PC-LAN-IP>:3030` on the phone (one-time Windows Firewall inbound rule for TCP 3030 required; see CLAUDE.md).

## Known balance signal (default map 16×12, seeds 1–200)

The first mover loses badly (~80/20 with the four-attack tables, seeds 1–200) — it advances into the second mover's threat range first, and the shorter 12-deep map makes it worse. Since the player (blue) now moves first, this is worth fixing soon: obvious levers are the AI's exposure term and/or spawning the second mover one row further back.
