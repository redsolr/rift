# Tactician — capability map

What the product does **today**. Update in the same commit as any feature-visible change. ✅ shipped · 🟡 partial · 🔲 planned (see `docs/concept.md`) · 🚫 deliberately not now.

## Engine (`src/sim`) — 2026-08-17

- ✅ Deterministic battle: `Battle(config, seed)`; mulberry32 RNG; identical logs for identical inputs (vitest-guarded).
- ✅ Grid: 16×12 default (river across the middle, three fords, forests on the flanks, hills, wall stubs); terrain = ground / forest (+2 def, cost 2) / hill (+1 def, cost 2) / water (impassable) / wall (impassable) / objective (+1 def). Dijkstra movement; enemies block, allies pass-through.
- ✅ Combat: `damage = max(1, atk + attack power − (def + terrain))`; healer heals `atk + power`; death; win when a side is wiped; draw at `maxTurns`.
- ✅ **Four attacks per unit (2026-08-18, `sim/attacks.ts`)** — Pokémon-style placeholder set per archetype (FE "combat arts" in spirit): each attack = flat **power** on atk, a **range** (or the weapon's own) and a **movement condition** — *stationary* (only without moving: Shield Bash / Cleave / Snipe / Blaze / Mend, +3) or *moved* (only after moving: Charge / Rush / Flare / Quick Heal, +1..+2) — plus a longer-reach lighter one (Long Thrust / Wide Swing / Quick Shot / Long Shot / Ember / Far Heal). Every attack also carries an **element** (physical / fire / ice / thunder / holy — e.g. Blazing Charge, Thunder Rush, Fire Arrow, Frost Bolt) and a **school** (physical / magic) — display-only today, the slot for weakness/resist tables. Deterministic, no accuracy yet. `Action.attack` names the attack id (attacks AND heals); `attack`/`heal` events carry its name; `Forecast.attack` = the one forecast. Engine validates the whole action **before** moving (a rejected attack no longer leaves the unit displaced). Threat tiles / danger zone = union of all four ranges. AI picks the best usable attack per (tile, target) — candidate labels read `Snipe → Wren`, the Damage term names it. Each attack has a **kind** (attack / heal): the healer owns three heals + **Staff Bash** (−3, adjacent) — every unit has at least one damaging attack; heals target wounded allies, attacks target enemies; `act()` refuses a kind mismatch. Threat tiles / danger zone use damaging attacks only.
- ✅ Turns: `firstTeam` phase → other phase (default red; the default config sets blue = the player); speed order within a phase (ties by id).
- ✅ Five archetypes: Knight, Fighter, Archer (range 2–3), Mage (1–2), Healer (1–2), each with default stats + personality.
- ✅ Utility AI with named score terms per candidate (attack / heal / move / wait); `decision` events carry the top-6 candidates.
- ✅ Personality (aggression, courage, discipline, intelligence, loyalty): discipline = order adherence + whim jitter; intelligence gates exposure/counter-risk (≥35) and focus-fire/overkill (≥70); courage scales exposure fear.
- ✅ Orders per unit: stance (hold/advance/pursue), target preference (nearest/weakest/wounded/ranged/healers), protect <ally>, avoid armored, do-not-pursue, retreat-below-HP%.
- ✅ Doctrine per team: aggression (very defensive → all-out) + objective (hold/advance/capture/protect).
- ✅ Event log = the only renderer input: turn_start, decision, move(path), attack, heal, wait, death, end.
- ✅ `runMany(config, seeds)` batch stats: win rates, avg turns, deaths/survivals per unit. `npm run sim -- N`. ~3.5 ms/battle.
- ✅ Share codes: config ⇄ URL-safe base64 (`#c=…`) — terrain alphabet `gfwvhos` (shrine included).
- ✅ **Runes (2026-08-18, `sim/runes.ts`)** — Dota-style power-ups. A **shrine** terrain (paintable in the editor; the default map has two, where the outer fords were) spawns a rune at battle start (before the opening banner — on the board from frame zero) and again **3 turns** after it is taken; the kind comes from the battle RNG (deterministic). A unit that ends its move on (or acts from) a rune-bearing shrine **picks it up** and carries ONE buff (a new rune replaces the old); buffs count down at the start of the owner's phase. **Haste** ⚡ = the unit **acts again immediately** (`refresh` event — FE Galeforce read; only a fresh pickup grants it) **and** +2 MOV for 3 turns (`effectiveMov` is the one definition — reach, threat map and AI all use it). **Double Damage** ✶ = (atk + power) × 2 before defence, 2 turns (the forecast reflects it). **Invisibility** ◌ = enemies cannot target you (target pools / AI candidates exclude you; `act` rejects it), 2 turns, **breaks when you attack or heal**. Events `rune_spawn` / `rune_pickup` / `rune_expire` are the only renderer input. AI: a `Grab rune: <kind>` term when standing on one (scaled by how much it helps this unit; weaker if already buffed) + a small `Rune nearby` pull. Vitest `runes.test.ts` asserts each promise. Not yet: truly hidden invisibility (invisible units render ghosted — untargetable, not unseen), rune-specific counter-play, spawn timers on the HUD.
- 🔲 Counterattacks, accuracy/crit, status effects, morale, command range, height, fog — only after the loop proves fun.

## Modes (`src/store`, `src/components`)

- ✅ **Manager**: set orders/doctrine → Start → command phase → Execute 1/3/5/all turns → watch → adjust → repeat. Both sides AI.
- ✅ **Manual — DEFAULT mode on load (2026-08-18) — FE command flow**: you control blue; click unit → blue reachable tiles → click tile → the card **previews on the new tile** and the in-board **command menu opens right away** (FE Three Hopes look: ink-smoke cloud — SVG turbulence-displaced blobs blurred so the edge FADES rather than blocks, no inner panel at all (the cloud is the surface) — hanging well to the RIGHT of the unit so it never covers the card, serif rows with ◆ bullets and hairlines, fixed columns, gold band + ➤ hand cursor on the hovered row): `Attack` · `Heal` (only for units that own heals) · `Wait` · `Cancel` (rows disabled with "—" when nothing is in reach). **Right-clicking one of your own units opens this menu at its current tile immediately** — no left-click first. Attack/Heal → the **skill panel** (`components/SkillPanel`): FE-style full-height framed panel on the RIGHT of the board (minimap + turn buttons step aside while it is open) — top = **Skills** list of that kind (element glyph, name, targets-in-reach or 🔒), bottom = **details** of the hovered (else first usable) skill: element · type (Physical/Magic), flavour line, **Dmg** (this unit's atk + power, before the target's defence — the battle bar shows the final number), **Rng**, **Hit** (100 until accuracy exists), **Crit** —, **Cost** — (no resource yet), **Use** (any time / only without moving / only after moving), and a green/red status line. Hovering a row previews its range on the board and its forecast in the battle bar; click picks it. Pick one → **target step — the picker list collapses (the right panel keeps the chosen skill's details)**; an FE **"Ⓡ Attack · Fire" band sits in world space right under the acting unit** (ink-smear, turns gold + pulses while a legal target is hovered: "right-click to confirm"; otherwise "pick a red target (n) · right-click empty = back") + red (or green for heals) target tiles + the battle-bar numbers carry it; click/right-click a target commits, right-click anywhere else backs out. `Back`/`Cancel`/**Esc** step back one page (target → picker → command → un-place). Fast paths: **right-click an enemy with a unit selected** moves it to a tile the enemy can be hit from (staying put if possible) and opens the **Attack picker** — you still choose the attack, then confirm on the target (right-click a wounded ally → the Heal picker); clicking a red target from the command page attacks with the best usable attack. **Right-click** = Civ-style one-click order: move to a reachable tile, or attack an enemy (from the current tile, or from a reachable tile in range); right-*drag* still pans (a drag never orders). **Esc** cancels the pending move / deselects. **Turn controls bottom-right of the board (2026-08-18)**, riding just above the battle bar (`--bb-h` published by the bar via ResizeObserver): **END TURN** = literally that: your remaining units wait where they stand and the enemy phase begins (the old "AI finishes" behaviour lives on only inside AUTO); **▶ AUTO** toggle = the AI plays *your* phases too (orders/doctrine) until you press ■ Auto again — switching it on during an idle phase of yours plays it out immediately. (Removed the duplicate End-turn button from the top HUD.) Walls are 0.6 tall to limit occlusion at the 45° angle.
- ✅ **Editor — map library (2026-08-18)**: a **Maps** section at the top lists every saved setup (terrain + units + doctrine + max turns) in **play order** (▲/▼ reorder, ✕ delete, rename inline, "+ Blank map", "+ Duplicate"); click a row to work on it; **every edit autosaves into the active map** (localStorage `tactician.maps`, hydrated on mount — SSR renders the default; the entry with id `default` is ALWAYS refreshed from the code's `defaultConfig()` on load, so a stale saved copy can never resurrect terrain the code changed). Loading a share code / the default setup **detaches** ("Unsaved setup — save as map") so it never overwrites a map. Manual/Manager play whatever map is active. No campaign flow yet — the order is the plan for one.
- ✅ **Editor**: click-drag terrain painting, place/erase/move units for either team, edit stats/name/team/archetype, resize map, max turns, clear terrain; **Run once** (watch), **Run 10/100/1000/5000×** with win bar + deaths/survivals; live personality sliders + orders on any unit.
- ✅ **Editor — RTS drag & drop + placement ghost (2026-08-18)**: tiles are the ground; everything else is an **object that sits on a tile** and is dragged. **Left-drag any unit card** and it rides the pointer tile-to-tile (lifted, ghosted); **left-drag a shrine or objective** (select tool) and a translucent ghost of it (violet slab + rune sigil / gold inlay ring) rides the pointer, the tile it leaves becoming ground. Under the pointer a **footprint** breathes **green** (legal) or **red with a ✕** (blocked: occupied, impassable, or a feature already there); the carried card tints green/red too; a top-centre hint pill reads `Drop Rook at 5,7` / `✕ Brakka is standing here`; a faint outline marks the tile the object came from. Pointer-up drops (illegal = snaps back), **Esc** cancels. **The palette tools preview the same way**: pick a unit archetype → a ghost card of it hovers on the pointer tile before you click; pick a terrain → a translucent block of it sits on the hovered tile. **"Show the potential" (RTS placement read)**: whatever is being placed — carried card, palette unit, or the selected unit standing still — paints its **move field + attack band from that tile** (blue/pink for you, red for the enemy) live as the pointer moves, computed from setup data (`reachable`/`standable` + `tilesInAnyRange`, no battle needed) and hidden while the drop is illegal. Click-to-move (select unit, click a free tile) still works as the keyboard-free alternative. Legality is one selector (`selectDropTarget`) shared by ghost, hint, drop and click-place. Not yet: dragging walls/forest/hill (they stay paint), multi-select / marquee drag, drag from the palette (palette is click-to-place with a ghost).

## Known balance signal (default map 16×12, seeds 1–200)

The first mover loses badly (~80/20 with the four-attack tables, seeds 1–200) — it advances into the second mover's threat range first, and the shorter 12-deep map makes it worse. Since the player (blue) now moves first, this is worth fixing soon: obvious levers are the AI's exposure term and/or spawning the second mover one row further back.
